## 01 — ERROR-MESSAGE ≠ ROOT-CAUSE TRACE
Purpose: diagnose platform rejection without assuming the platform label names the true defect.
STATE/input: rejection/error plus artifact.
Doors/casts: exact error phrase → operator forums/Reddit → official spec → cited page/object → neighboring causes.
Transformation: error label → candidate causes → inspect named object/page → test candidates against spec.
DONE/output: evidenced root cause or bounded unresolved set.
Stop: one cause explains artifact + platform rule + successful correction, or remaining candidates are explicitly unresolved.
Contradictions: preserve cases where identical labels had different causes.
Failure boundary: never universalize one operator fix.
Fit-test: reusable for KDP, compilers, APIs, app stores, hardware diagnostics.
Pressure test: KDP “bleed” reports include true bleed geometry, live-element intrusion, and page/unit anomalies.

## 02 — BEFORE/AFTER DELTA SEARCH
Purpose: exploit “it worked before; tiny change broke it.”
STATE: previous PASS + current FAIL.
Doors/casts: exact symptom + “worked before”/“after update”/“re-upload” → community → official change/spec.
Transformation: enumerate changed variables, including platform-side change; rank by temporal fit.
DONE: minimal causal delta identified or platform regression remains plausible.
Stop: smallest reproducible delta found.
Contradictions: compare unchanged-user-file reports with genuine user-file changes.
Failure boundary: temporal sequence is not proof of causation.
Fit-test: software updates, publishing pipelines, deployments, device failures.
Pressure test: 2026 KDP TOC reports clustered after light edits/re-upload and were later reported resolved by support.

## 03 — CROSS-OUTPUT SAME-INPUT DIFFERENTIAL
Purpose: use one artifact behaving differently across outputs to isolate hidden conditions.
STATE: nominally same input, different result.
Doors/casts: “same file” + output variants/platforms → operator reports → output-specific specs.
Transformation: hold source constant; enumerate differing renderer/product/settings/reviewer/manufacturing variables.
DONE: discriminating variable(s) or bounded hypotheses.
Stop: difference predicts pass/fail across cases.
Contradictions: preserve reports where same input passes both.
Failure boundary: “same file” does not mean same processing path.
Fit-test: paperback vs hardcover, browsers, OSes, printers, model variants.
Pressure test: same KDP interior accepted for hardcover while paperback flagged selected pages.

## 04 — COMMUNITY-CLUSTER / PLATFORM-REGRESSION DETECTOR
Purpose: distinguish local defect from service-side incident.
STATE: surprising new failure despite previously valid workflow.
Doors/casts: exact error + tight date window + Reddit/forum/community + official support acknowledgement/status.
Transformation: collect independent near-simultaneous reports; compare tools/files; seek provider acknowledgement/resolution.
DONE: local, service-side, or unresolved classification with confidence.
Stop: diverse independent cases + provider evidence, or evidence remains insufficient.
Contradictions: actively seek unaffected operators in same window.
Failure boundary: multiple posts may copy one another; count independence, not volume.
Fit-test: SaaS regressions, APIs, marketplaces, cloud outages.
Pressure test: KDP TOC and Previewer formatting reports show value of dated clustering and provider acknowledgement.

## 05 — USER-MENTAL-MODEL FAILURE SEARCH
Purpose: find failures caused by a reasonable but wrong model of how a system works.
STATE: operator follows intuitive workflow but output fails.
Doors/casts: “I thought”/“assumed”/“does this mean” + symptom → beginner forums → official conceptual docs.
Transformation: extract assumed model; contrast actual mechanism; derive teaching/check function.
DONE: misconception + corrective operational rule.
Stop: model difference explains observed failure and official behavior.
Contradictions: context where intuitive model is actually valid is retained.
Failure boundary: do not label user error when platform behavior is ambiguous.
Fit-test: reflowable ebooks, bleed, permissions, networking, version control.
Pressure test: fixed page breaks designed around one Kindle screen fail when screen/font size changes.

## 06 — PAGE/OBJECT LOCALIZATION CAST
Purpose: turn broad rejection into a small inspectable target.
STATE: multi-page/multi-object artifact with vague failure.
Doors/casts: error + page numbers/alerts → operator walkthroughs → preview/log diagnostics.
Transformation: global FAIL → named pages/objects → compare failing vs neighboring passing instances.
DONE: localized anomaly or proof failure is global/systemic.
Stop: smallest failing unit isolated.
Contradictions: if identical neighboring objects differ, escalate to hidden metadata/rendering variables.
Failure boundary: visual similarity does not prove file-level identity.
Fit-test: books, datasets, test suites, batch jobs, media encodes.
Pressure test: operators found single nudged pages among otherwise apparently identical KDP layouts.

## 07 — OFFICIAL-RULE + OPERATOR-EDGE BRIDGE
Purpose: combine normative rule with lived failure modes without letting anecdotes override policy.
STATE: official specification exists but operators still fail.
Doors/casts: official docs first/parallel; then exact rule terminology in Reddit/forums/failure reports.
Transformation: RULE → known misreadings/edge cases → diagnostic checks.
DONE: executable check that remains anchored to current official rule.
Stop: rule and representative failure mechanisms covered; disagreement labeled.
Contradictions: official rule controls compliance; operator evidence controls diagnostic breadth, not policy truth.
Failure boundary: stale community advice cannot supersede current official spec.
Fit-test: KDP, tax forms, APIs, standards, device setup.
Pressure test: KDP bleed dimensions are official; operator reports reveal multiple ways files can appear compliant yet fail.

## 08 — DOWNSTREAM-INVALIDATION TRIGGER SEARCH
Purpose: discover which “small” upstream changes force downstream rechecks.
STATE: artifact previously DONE; upstream edit occurs.
Doors/casts: “after changing/editing” + downstream symptom → operator reports → dependency/spec docs.
Transformation: edit → changed derived properties → affected downstream objects → minimal revalidation set.
DONE: dependency-trigger map.
Stop: every materially affected downstream output has a recheck rule; unaffected outputs need not rerun.
Contradictions: distinguish deterministic dependencies from transient platform regressions.
Failure boundary: do not rerun whole pipeline by habit.
Fit-test: pagination→gutter/cover/TOC; code→tests/builds; data→reports/models.
Pressure test: KDP states page-size changes shift text/page count and can require margin rechecking; operators report TOC issues after tiny edits.
